# ACP dev integration validation (credential-free, mock vendor)

Re-runnable acceptance contract for the `ACP -> codex (app-server) -> model
provider` path, archived from the one-off rig-0.44 validation drivers. The
vendor is a local mock server that records every model HTTP request, so each
scenario is a machine-checked assertion over the real wire bytes. No real
credentials, account data, or captured screenshots are used: the API key is a
dummy value the runner sets itself, and the only images are synthetic
solid-color palette PNGs generated by `shot-server.mjs`.

## Wires

The same six scenarios run on all three provider wires — `chat`
(OpenAI Chat-Completions), `responses` (OpenAI Responses passthrough) and
`anthropic` (Anthropic Messages) — for 18 executable rows total. The mock
serves all three on one port (`/v1/chat/completions`, `/v1/responses`,
`/v1/messages`) and the wire's native SSE shapes; `scenarios.json` is the
machine-readable scenario table the merged summary is checked against.

## Files

- `mock-vendor-server.mjs` — tri-wire mock vendor with a JSONL request
  recorder (each record carries its wire, Authorization and x-api-key).
  Answers are scripted; recall/compaction answers are derived from the
  actual incoming request, so passing still proves codex sent the bytes.
  Screenshot follow-ups are VERIFIED, not assumed: the typed image of the
  CURRENT turn's tail is extracted per wire (responses
  `function_call_output.output[].input_image`, anthropic `tool_result`
  nested image blocks, chat `image_url` parts), decoded by a minimal PNG
  decoder (base64 -> IHDR -> IDAT inflate -> unfilter, filters 0-4, 8-bit
  RGB/RGBA) and answered with the CLASSIFIED color name. A tail without a
  typed image answers kind `image-missing`; an undecodable image answers
  `image-undecodable`; byte-identical re-use of an image already answered
  by an earlier tool round answers `image-stale`. An image that exists
  only in older history never satisfies the current round.
- `shot-server.mjs` — minimal MCP stdio server exposing `take_screenshot`.
  Every call returns a solid-color 64x64 PNG (six-color palette,
  round-robin; per-process nonce + call counter encoded in the final pixel
  keeps each served image byte-unique so re-served old images are
  detectable). With `SHOT_TRUTH_PATH` set it appends ground-truth records
  `{ts, mcpCallId, color, event: start|complete}` to that JSONL file — the
  `start` record lands before the `SHOT_TAKE_MS` delay so cancel-during-
  tool rounds can prove the tool really began.
- `acp-mock-validation-driver.ts` — the six-scenario driver with assertions.
- `run-acp-mock-validation.sh` — validates the binary receipt (sha256),
  starts the mock, sets the dummy key, runs the driver. `VAL_WIRE` selects
  the wire (default `chat`); `VAL_ROOT` overrides the artifact directory.
- `run-all-wires.sh` — runs all three wires against one binary and merges
  the per-wire `results.json` plus `scenarios.json` into `summary-18.json`.
- `scenarios.json` — machine-readable scenario/contract table.
- `stress-50.ts` — the 18-rounds-per-wire stress driver (see below).

## Scenarios

| Step | Contract |
|---|---|
| S1 | session bootstrap with an MCP screenshot server |
| S2 | the named env var reaches the model request (Authorization header), the configured model id is used for both the primary turn and automatic title request, and a full turn completes |
| S3 | the MCP image tool's output reaches the next model request as typed `image_url` content (data URL), after the tool actually ran |
| S4 | `session/cancel` mid-stream resolves the prompt with `stopReason: "cancelled"` |
| S5 | `/compact` then a continuation turn on the same session |
| S6 | kill the agent, `session/load` on a fresh process; recall succeeds only when the token is genuinely present in the resumed request history |

The driver writes a `results.json` artifact (binary path, sha256, per-step
outcomes) and exits non-zero when any step fails.

## Run

```bash
# Build the candidate first, then all three wires (18 rows, merged summary):
scripts/acp-validation/run-all-wires.sh /path/to/codex [expected-sha256]
# Or a single wire:
VAL_WIRE=anthropic scripts/acp-validation/run-acp-mock-validation.sh /path/to/codex [expected-sha256]
# 54-round stress (18 fixed rounds per wire — 4 VERIFIED tool-image rounds
# per wire (12 total), cancels at three stages with proven preconditions,
# compactions, cold restarts; per-round HTTP/socket/PID-tree receipts,
# aux-request classification, and post-shutdown leak assertions):
scripts/acp-validation/run-stress.sh /path/to/codex [expected-sha256] ALL
# Negative self-check for the probe hardening (optional, NOT run by the
# table run; the invocation must exit non-zero):
STRESS_SIMULATE_PROBE_FAILURE=stats scripts/acp-validation/run-stress.sh /path/to/codex
```

## Stress hardening (review items 6 and 8)

`run-stress.sh` sets a fresh `SHOT_TRUTH_PATH` per run and per wire. The
stress driver additionally:

- **Verifies tool-image rounds end to end.** After each completed image
  round it reads the newest `complete` ground-truth record and asserts the
  agent's final message EQUALS that color (case-insensitive). Only
  verified rounds count toward `verifiedImageRounds`; the run fails below
  4 per wire (12 across the three wires). Cancel-during-tool rounds never
  count. Mock answers `image-missing` / `image-stale` /
  `image-undecodable` fail the round with that reason.
- **Proves cancel preconditions.** before-headers waits until the mock has
  recorded the hang request (arrival signal — the hang kind never
  answers); mid-stream waits for an actual stream delta; during-tool waits
  for the shot-server `start` truth record. A timed-out precondition
  fails the round instead of silently cancelling. After each cancel no
  additional MAIN model request may arrive for that turn; title/guardian
  auxiliary requests are identified by their recorded kind and counted in
  `auxRequestCounts`/`auxRequestTotals` instead of being tolerated.
- **Fails loudly on unavailable probes.** Any `/stats` fetch error,
  process-listing error, or (on Linux) unreadable `/proc` entry is listed
  in `probeFailures` and fails the run — never a silent -1.
- **Tracks the real process tree.** The driver knows the ACP wrapper PID
  it spawned; the app-server child and any shot-server / other descendants
  are resolved via `ps` and recorded per round with start times (`lstart`)
  to guard against PID reuse. After every generation shutdown (cold
  restarts and the final shutdown) all tracked PIDs must be gone within
  10s (35s only for the exact curated-plugin `git ls-remote` update check),
  or the run fails listing the expired processes (`leftoverShotServers`
  counts the shot-server role). Expired tracked processes are cleaned up
  after saving the failed observation; successful cleanup never changes
  that failure into a pass. PID identity is rechecked immediately before
  cleanup. Nothing the driver did not spawn is killed, and
  no whole-machine `pgrep` is used as the residue check.
- **Has a negative self-test.** `STRESS_SIMULATE_PROBE_FAILURE=stats|pgrep`
  breaks a probe class on purpose; the run must then exit non-zero, which
  is how the teeth above are proven on demand.

Cancel counting starts before sending `session/cancel`, including additional
requests arriving before its prompt acknowledgement. The local contract
regressions run with `node --import tsx --test
scripts/acp-validation/stress-contracts.test.mjs`. Real-model validation has a
separate [shared request budget runner](../live-validation/README.md).

`CODEX_PATH` is explicit — no silent default binary. Passing the expected
sha256 (second arg or `EXPECT_CODEX_SHA256`) makes the run refuse to start on
a receipt mismatch.

## Boundary

This mock proves protocol/contract behaviour only. It does **not** prove a
real vendor serves these requests, and it cannot prove vision: the S3 model
answer is scripted. Real-vendor and real-vision validation stays a separately
authorized paid run (see the rig-production notes in the codex repo).

## Review corrections (2026-10-16)

The initial report of two codex product defects was incorrect. Re-running the
same binary with a corrected mock and driver passes all six scenarios:

- The mock treated the guardian review's quoted transcript as a new user tool
  request, despite the review declaring no tools and requesting a structured
  `{ "outcome": ... }` JSON object. Its fabricated screenshot call failed as
  `unsupported call`; the main turn consequently reported invalid guardian
  JSON. The mock now handles guardian and title schemas before main-turn
  scripting, and issues a tool call only for an advertised tool.
- Rig merges adjacent user messages into text parts. Concatenating these parts
  re-matched the interrupted essay ahead of the **present** compaction or
  continuation instruction. The mock now uses the latest text part and gives
  compaction/continuation/recall priority over old screenshot history.
- MCP completion notifications omit the start notification's title. The driver
  now correlates tool names by `toolCallId`, rather than treating the id as the
  tool name and reporting a false incomplete result.

The review did reveal one separate ACP product defect: automatic titles used
`gpt-5.6-luna` against every custom provider. `TitleGenerator` now captures the
active model for custom providers before awaiting ephemeral-thread creation;
OpenAI and the two built-in Bedrock provider ids retain their existing
preferred model. S2 asserts the title's actual outgoing HTTP model id.

The mock records a `kind` per request and permits at most 48 requests per run,
including guardian and title requests. The six-scenario contract proves
transport and history behaviour, not vision quality or security decisions;
its guardian answer is a deterministic fixture.

Run its mock contracts (tri-wire normalization, SSE emitters, path routing,
shared retry budget, error inputs) and strict TypeScript checks with:

```bash
npm run test:acp-validation
npm run typecheck
npx vitest run --no-file-parallelism src/__tests__/TitleGenerator.test.ts
```

The root TypeScript project includes `src` explicitly; the validation driver has
its own strict `tsconfig.json`, also checked by `npm run typecheck`, so archiving
scripts outside `src` does not break the production root directory contract.

Review receipt before the final codex rebuild: all six scenarios passed with
9 recorded model HTTP requests; codex binary SHA-256
`7fba393f9cf5549dbcd14a78d85636dc8d3e2da13f4ad7d45a841bc3f6635d75`.
The binary hash is the identity under test, not a claim that a rebuilt final
source commit was exercised. Use the runner's expected-hash argument when
validating a newly built binary.

## Final-acceptance runner receipts

The stress and restored-usage runners default to OS-reserved port `0` and
read a readiness receipt written atomically by their own mock process. A
different server answering `/health` cannot satisfy startup. Explicitly
requesting an occupied port fails; it is not retried or silently replaced.
Shutdown waits for the owned mock process to exit. With `VAL_ROOT` and wire
`ALL`, each wire keeps its own subdirectory instead of overwriting receipts.

`mock-ready.json` records the owning PID, actual port, mock source SHA-256 and
request/tool budgets. `run-long.sh` saves its starting mock hash in
`mock-source-sha256.txt` and requires each mock instance to match it. Editing
or swapping the mock during a long run therefore fails startup rather than
silently combining different versions. This pins the mock; it is not a
replacement for the separate Codex binary receipt or full ACP source provenance.

The historical 94-batch/5076-round receipt used mock `5869e00` without
`0e0dcc3`; it does not prove the latest mock completed another four-hour run.
Current midnight handling is checked deterministically by injecting the
2026-10-18 environment-context shape into all three native request wires,
both as a separate message and inside the image-result message. Negative
cases preserve missing-image failures, reject ordinary tool output quoting
an image label, and prevent historical screenshots answering a newer turn.
No wall-clock change or four-hour rerun is needed to exercise those branches.

Chat HTTP fixtures emit usage only when `stream_options.include_usage=true`,
so omitting that request flag cannot be hidden by an unconditional mock usage
frame. The restored-usage driver isolates notifications by process and
session and checks `used=5` plus the context-window value before/after warm
reload, cold load and continuation. This verifies the public `usage_update`
last-turn values; cumulative internal token-ledger inheritance is covered by
the ACP product unit tests, not inferred from the fixed five-token fixture.

## Environment gateway / native Responses closure

The six-scenario driver also accepts `VAL_GATEWAY_ENV=1`. In this mode it
starts with an empty `config.toml` and supplies the public `CODEX_*` gateway
environment variables to the real ACP process. Inherited `CODEX_*`,
`NUWAX_*`, `OPENAI_API_KEY` and `MODEL_PROVIDER` routing is removed first;
the explicit candidate binary and local dummy credential are then added.
This exercises the adapter's environment gateway rather than a prewritten
provider configuration.

```bash
# Explicit native Responses, followed by default rig on the same wire:
VAL_GATEWAY_ENV=1 VAL_BRIDGE=native VAL_WIRE=responses \
  scripts/acp-validation/run-acp-mock-validation.sh /absolute/path/to/codex EXPECTED_SHA256
VAL_GATEWAY_ENV=1 VAL_BRIDGE=default VAL_WIRE=responses \
  scripts/acp-validation/run-acp-mock-validation.sh /absolute/path/to/codex EXPECTED_SHA256
# Domestic-model protocol entry points, still with local dummy fixtures:
VAL_GATEWAY_ENV=1 VAL_WIRE=chat \
  scripts/acp-validation/run-acp-mock-validation.sh /absolute/path/to/codex EXPECTED_SHA256
VAL_GATEWAY_ENV=1 VAL_WIRE=anthropic \
  scripts/acp-validation/run-acp-mock-validation.sh /absolute/path/to/codex EXPECTED_SHA256
```

`VAL_BRIDGE=default` omits `CODEX_BRIDGE`, proving the default selection;
`rig` selects it explicitly. `native` requires Responses. Each run additionally
records a mandatory S7 postflight: all model calls used the exact selected
path, model and dummy authentication, and rig's request-capture bodies match
the mock's received bytes. A native run must receive real HTTP model calls
and create zero rig capture entries; a rig run must capture every request.
The stable six-scenario table remains the input to `summary-18.json`; a failed
S7 still makes the per-wire runner and the combined runner fail.

S2 also requires the numerical `usage_update.used=5` fixture value and a
positive context window. S6 clears prior traces before cold restart and
requires the restored usage update before sending its recall prompt. These
are deterministic protocol contracts, not real-vendor usage or vision claims.
